**JTAG** 是 **Joint Test Action Group**（联合测试行动小组）的缩写，通常指代 **IEEE 1149.1** 标准。

它是一种**国际标准接口**，主要用于芯片的**边界扫描测试**（生产测试）和**在线调试**（开发调试）。在嵌入式开发（如 STM32、FPGA、ARM）中，它是工程师用来给芯片"看病"和"下命令"的最重要工具。

---

### 1. 核心作用：JTAG 能做什么？

JTAG 主要有两大功能：

1. **边界扫描测试 (Boundary Scan)**：

   - **出厂测试**：在芯片焊接到电路板后，不需要物理探针，就能通过 JTAG 检测引脚是否虚焊、短路，或者 PCB 走线是否连通。
   - **原理**：芯片内部每个 I/O 引脚旁都有一个"扫描单元"，JTAG 可以控制这些单元读取或写入电平。

2. **在线调试 (In-Circuit Debugging)**：

   - **开发必备**：这是开发者最常用的功能。通过 JTAG 接口，电脑上的调试器（如 J-Link, ST-Link）可以：
     - **烧录程序**：将代码写入芯片 Flash。
     - **单步执行**：一行一行地运行代码，观察变量变化。
     - **断点调试**：让程序停在某一行，检查寄存器状态。
     - **内存读写**：直接查看或修改芯片内部的 RAM/寄存器数据。
   - **优势**：即使芯片程序跑飞了（死机），只要供电正常，JTAG 通常也能强行接管芯片控制权。

---

### 2. 核心引脚定义 (最少 4 根线)

标准的 JTAG 接口至少需要 **4 根信号线** 加上 **GND**：

| 引脚缩写 | 全称 | 方向 | 含义与作用 |
|----------|------|------|-----------|
| **TCK** | Test Clock | 输入 | **测试时钟**。由调试器提供，为整个通信过程提供同步心跳。 |
| **TMS** | Test Mode Select | 输入 | **测试模式选择**。控制芯片内部状态机（FSM）的跳转路径（如：是从"运行"跳到"暂停"，还是跳到"复位"）。 |
| **TDI** | Test Data In | 输入 | **数据输入**。调试器通过这根线串行发送指令或数据给芯片。 |
| **TDO** | Test Data Out | 输出 | **数据输出**。芯片通过这根线串行返回数据或状态给调试器。 |
| **TRST** | Test Reset | 输入 | **测试复位** (可选)。用于主动复位 JTAG 状态机。如果不接，可以通过 TMS 序列软复位。 |
| **GND** | Ground | - | **地线**。必须连接，提供电平参考。 |

> **💡 记忆口诀**：**T**ime (TCK), **M**ode (TMS), **D**ata **I**n (TDI), **D**ata **O**ut (TDO).

---

### 3. JTAG vs. SWD：有什么区别？

在 STM32 开发中，你经常会听到 **SWD** (Serial Wire Debug)。它们都是调试接口，但有以下区别：

| 特性 | **JTAG** | **SWD** (Serial Wire Debug) |
|------|----------|-----------|
| **引脚数量** | **多** (至少 4 根信号线 + GND，通常 5-6 根)。 | **少** (仅 2 根信号线 **SWDIO, SWCLK** + GND)。 |
| **功能** | 支持边界扫描测试 + 调试。功能最全。 | 仅支持调试和烧录。**不支持**边界扫描测试。 |
| **速度** | 较快，但在高频下受限于引脚多带来的干扰。 | 非常快，且抗干扰能力较强，适合高速调试。 |
| **占用资源** | 占用较多 GPIO 引脚。 | 极大节省引脚资源（这对引脚少的芯片很重要）。 |
| **应用场景** | FPGA 调试、复杂板卡生产测试、老款 ARM 芯片。 | **现代 STM32 开发的主流选择** (如 ST-Link 默认模式)。 |
| **兼容性** | 许多调试器（如 J-Link）同时支持 JTAG 和 SWD。 | 同上。 |

> **现状**：虽然 JTAG 功能更强大，但在日常的 STM32 单片机开发中，由于 **SWD 更省引脚且速度够快**，大家更倾向于使用 SWD 模式。但在 FPGA 开发或需要检测 PCB 焊接质量的场景下，JTAG 依然是不可替代的。

---

### 4. 工作原理简述 (状态机)

JTAG 的核心是一个内部的状态机（TAP Controller）：

1. **时钟驱动**：TCK 每跳动一次，状态机可能跳转。
2. **模式控制**：TMS 的电平高低决定了状态机往哪个方向跳（比如进入"移位寄存器"状态还是"捕获"状态）。
3. **数据传输**：当状态机进入特定状态时，数据通过 TDI 移入芯片，或通过 TDO 移出芯片。
4. **复位**：如果 TMS 保持高电平超过 5 个 TCK 周期，状态机会强制复位到初始状态（Test-Logic-Reset），防止死锁。

---

### 5. 常见硬件接口

- **20-pin IDC 接口**：传统的标准 JTAG 接口，体积大，常见于老式开发板或 FPGA 开发板。
- **10-pin 紧凑接口**：常见的 ARM 调试接口定义。
- **SWD 转接板**：现在很多调试器（如 ST-Link V2/V3, J-Link OB）直接引出 4 根线 (VCC, GND, SWDIO, SWCLK)，通过杜邦线连接，不再使用庞大的排针座。

### 6. 总结

- **JTAG** 是芯片调试和测试的**通用语言**。
- 它通过 **TCK, TMS, TDI, TDO** 四根线实现对芯片内部的完全控制。
- 它是**生产测试**（查虚焊）和**深度调试**（看寄存器、单步执行）的神器。
- 在 STM32 日常开发中，虽然 **SWD** 更常用（因为线少），但 SWD 本质上是 JTAG 协议的一个精简变种，底层的调试逻辑是一脉相承的。

**一句话结论**：JTAG 是工程师的"听诊器"和"手术刀"，让你能深入芯片内部，查看状态、修改数据、定位 Bug。
